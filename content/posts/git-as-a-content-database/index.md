> 示例文章。部署配置已提供，实际仓库和托管服务待作者选择。

对于以文章为主的个人站点，文件加 Git 是一种直接的内容管理方式。它让正文、图片和分类索引共享版本历史。

## 每次修改都有一个版本

文章中的一句话和一张图片，可能在同一次修订中发生变化。一起提交，可以保留它们之间的对应关系。

```bash
git add content/
git commit -m "docs: publish my first note"
git push
```

自动部署启用后，推送会触发构建。只有检查通过的版本才会被交付到托管服务。

## 把内容与构建产物分开

源文件进入仓库，`dist/` 由构建生成。保留源文件就保留了重新构建的能力，生成结果不需要反复提交。

| 保存到 Git | 由流水线生成 |
| --- | --- |
| Markdown 正文 | HTML 页面 |
| 原始插图 | 处理后的图片 |
| 分类与标签索引 | 搜索索引 |
| 页面组件与样式 | 压缩后的静态资源 |

## 回滚的是一次完整修改

如果发现内容或样式问题，可以通过新的提交撤销相关修改。相比手动修补服务器文件，这样更容易保留变更记录。

## 适合的边界

这种方式适合内容更新频率适中、作者数量有限、可以接受构建延迟的博客。实时协作、动态评论或大量用户数据，则可能需要额外的服务。

先把文章管理做好，再根据实际需要增加功能，能让维护成本更可控。
