> 示例文章，用于展示工程实践分类。

一个小工具能否长期使用，往往取决于下一次运行它时，需要重新记住多少事情。

## 给常见路径一个默认值

新建文章时，通常需要创建目录、写入 frontmatter、建立图片文件夹，并登记分类。把这些操作收进一个命令，可以减少遗漏。

```bash
npm run new -- my-first-note --title "我的第一篇笔记" --category notes
```

默认创建草稿，让作者先关注内容。真正公开之前，再运行独立的发布检查。

## 让错误说明下一步

一个「执行失败」的提示没有提供多少信息。更有帮助的错误会说明具体字段和修复方向：

```text
my-first-note 的分类不存在：frontendd
```

定位到问题的成本降低之后，校验才更可能被日常使用。

## 避免悄悄覆盖

创建操作应该在目标已存在时停止，而不是覆盖原文件。稳定的工具应尽量减少意料之外的副作用。

## 把复杂度留在恰当的位置

不要为了未来可能发生的需求，提前增加过多配置。先让最常见的一条路径顺畅，再从真实的重复中提炼能力。
